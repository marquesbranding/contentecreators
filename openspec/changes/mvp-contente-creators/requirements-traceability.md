# Requirements Traceability

## Source precedence and status legend

Precedence is: confirmed user brief and clarifications → `Contente Creators Beta - Roadmap.docx` → explicit implementation decision. `Planned` means the resolved requirement is in Beta scope, `Replaced` means the prompt changed the DOCX behavior, `Excluded` means it is deliberately outside the Beta, and `Launch input` means implementation can use a safe local placeholder but production cannot launch without client-owned content/configuration.

## Coverage gates

- Every `Planned` row must have at least one unchecked task until implemented and at least one spec scenario that can become an automated or acceptance test.
- Every `Replaced` row must have a regression/scope test proving the superseded DOCX behavior was not accidentally implemented.
- Every `Excluded` row is verified by task group 28 before release.
- Every `Launch input` remains visibly blocking in task group 27; placeholders must not be mistaken for client approval.
